# Modelo · Retrospectiva

Capítulo 12, seção 12.6. Quinze minutos depois do merge, por escrito, para tirar pelo menos uma mudança concreta num arquivo do projeto. Guarde em `docs/retrospectivas/AAAA-MM-DD-<funcionalidade>.md`.

## Modelo

```markdown
# Retrospectiva: <funcionalidade> (<AAAA-MM-DD>)

## As cinco perguntas

1. **O que funcionou?** Em que etapas o agente acelerou o trabalho sem custo de revisão?
   <resposta>
2. **O que falhou ou exigiu correção?** De que tipo foi a falha (passageira, permanente, de lógica ou sem progresso) e que camada de verificação a pegou?
   <resposta>
3. **O que o agente fez que você não teria feito?** Foi uma boa ideia ou um excesso?
   <resposta>
4. **Onde você relaxou a revisão?** Em que momento você aprovou sem ler?
   <resposta>
5. **O que muda no próximo pedido?** Uma linha no CLAUDE.md, um hook, uma skill, um critério de delegação?
   <resposta>

## Registro

| Etapa | O que aconteceu | Tipo de falha | Que camada pegou | O que muda |
|---|---|---|---|---|
| | | | | |
| | | | | |

## O que delegar da próxima vez

- **Delegaria de novo:** <tarefas>
- **Delegaria só em parte, com revisão passo a passo:** <tarefas>
- **Não delegaria:** <tarefas>

## A mudança concreta

<O arquivo que mudou por causa desta retrospectiva e o que mudou: uma linha no CLAUDE.md, um hook, uma skill ou um critério de delegação.>
```

## Como usar

- A retrospectiva é de **processo**, sobre o que o fluxo deixou passar. Não é de culpa, sobre quem errou.
- Termine escrevendo a mudança concreta. Pergunta de controle: existe, no repositório, um arquivo que mudou por causa desta retrospectiva? Se não, ela virou conversa.
- Releia a tabela de delegação do capítulo 11 (seção 11.8) com a sua entrega à frente. Uma tarefa que o agente fez bem pode subir de nível de autonomia; uma que exigiu muita correção volta para a revisão passo a passo.
